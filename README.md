# 食护家 FoodLensCare · 食品标签初版

> 面向老年家庭的食品标签智能解读工具。
> 老人拍一张食品包装照片，系统用一句听得懂的话告诉他「这个能不能吃、为什么」。
>
> 2026 年第十四届全国大学生数字媒体科技作品及创意竞赛 · 自主选题类 · 移动与网络应用开发

本仓库是参赛方案对应的**可运行基础 Demo**：打通方案 3.1 的五步闭环，
并把方案 4.3 的规则层、4.2 的双通道感知层、3.3 的适老化规范逐条落地。

## 一、三种打开方式

### 方式 A · 点开就用（在线体验）

**https://metal783.github.io/foodlenscare/**

不需要安装任何东西，手机浏览器直接打开即可。这是给评委最省事的方式。
（在线版内容是单文件版的副本，由 `python tools/prepare-pages.py` 同步，见 [docs/README.md](docs/README.md)。）

### 方式 B · 电脑双击启动（新版 OCR 推荐）

双击根目录的 **`启动新版OCR.cmd`**（需要 Python）。它会启动本机服务并自动在浏览器打开新版 OCR，使用期间保持终端窗口开启即可。手机局域网体验使用 **`启动手机体验.cmd`**，它同样会自动打开电脑端页面。

### 双击 HTML · 同样使用新版 PaddleOCR

直接双击仓库根目录的 **`FoodLensCare-standalone.html`**。

这一个文件里装下了全部 35 个源模块、样式与页面结构（约 272 KB，不含 OCR 资源）。
双击后可直接选择照片，使用与服务版相同的 PaddleOCR 和 PP-OCRv5 mobile 模型。由于浏览器不允许网页读取旁边的模型文件，双击版从固定线上资源地址下载引擎和模型，照片仍在本机识别，不会跳转网页。首次真实识别需要联网；需要从本地资源加载时可使用 `启动新版OCR.cmd`。

改了源码之后重新生成：

```bash
node tools/bundle-standalone.mjs        # 重新打包出单文件版
python tools/check-standalone.py        # 校验它在 file:// 下能跑通 7 个页面
```

### 方式 C · 多文件开发版（用于日常开发）

```bash
python tools/serve.py
```

需要本地服务的原因：浏览器在 `file://` 下会以 CORS 为由拒绝加载 ES Module，
直接双击 `index.html` 会白屏；Service Worker 在 `file://` 下也无法注册。
这一版比单文件版多两项能力：**PWA 离线缓存**和**可「添加到主屏幕」**。

```bash
# 终端会打印两个地址
#   本机打开：http://127.0.0.1:5173/
#   手机打开：http://192.168.x.x:5173/   ← 手机与电脑连同一个 Wi-Fi
```

手机地址生成二维码后扫码即可在真机体验。需要二维码时先 `pip install qrcode`，
脚本会自动打印；不想装依赖就手动把地址发到手机。

### 三版的关系

| | 在线体验版 | 单文件版 | 多文件开发版 |
| --- | --- | --- | --- |
| 打开方式 | 点链接 | 双击 HTML | `python tools/serve.py` |
| 依赖 | 无 | 无 | 需要 Python（或任意静态服务） |
| 联网 | 首次加载需要；缓存后可离线 | 页面与演示可离线，真实 OCR 首次需要联网 | 本地 OCR 无需外网；手机离线缓存另受浏览器安全上下文限制 |
| 页面与样式 | **完全一致** | **完全一致** | **完全一致** |
| 离线缓存 / 加桌面 | 有（`docs/sw.js`） | 无（浏览器限制） | 有（PWA） |
| 适合 | 交给评委体验 | 提交、演示、发给别人 | 改代码、调样式 |
| 生成方式 | `tools/prepare-pages.py` | `tools/bundle-standalone.mjs` | 直接编辑 `src/` |

三版来自同一份 `src/`：在线版与单文件版都是把 `index.html` 与 `src/` 内联后的产物，
由打包脚本同步。当前已验证源码版、Pages 入口和双击版的页面及操作流程；历史逐像素截图结果不作为本次更新的验证结论。

**零配置可演示**：首页内置用例可以离线体验结论、播报和记录。
真实拍照默认使用本机中文 OCR，无需接口密钥。照片不上传，识别真实文字，不会用演示商品替代照片内容。

### 拍照读取食品配料表

首页使用主拍照按钮或「从相册里选一张」，预览后确认读取。「拍照帮助」中保留配料表引导页。
手机测试：运行 `python tools/serve.py --mobile --no-qr`，让手机与电脑连接同一 Wi-Fi，再用手机浏览器打开终端打印的「手机打开」地址。点击「拍配料表」请求后置摄像头；若系统先显示选择菜单，请选择「拍照」。电脑端通常显示文件选择器。手机试用模式仅公开运行页面和 OCR 依赖。
支持取消选图、重拍、取消读取和结果页补拍；取消重拍会保留原照片，补拍回到配料表页。
识别到的标签原文支持朗读，全文放在可展开区域；未读到的字段保持空值。识别配料中的疑似过敏冲突会先提醒，营养候选在对照包装核对后才用于摄入计算。
包装二维码识别功能已取消；本地服务生成的二维码只用于打开网站。

本地服务版、在线版附带 OCR 引擎与中文模型（支持常见英文混排），不需要访问云端识别接口；首次运行后可缓存模型。
双击单文件版受浏览器文件访问限制，PaddleOCR 引擎和模型从项目的 GitHub Pages 固定资源地址下载，首次识别需要联网；本地服务与在线版从同源加载同一引擎和模型。
默认区域识别采用 PaddleOCR.js 0.4.2 与 PP-OCRv5 mobile 中文模型，先定位文字框，再按位置整理配料和营养表。识别出的每 100 克/毫升营养含量会预填到核对框，并显示对应原文；不会把 NRV% 当成含量，每份口径及多口径有歧义时需手动确认。

OCR 结果可能有错字、漏字。结果页可编辑完整配料、致敏提示和营养值，勾选对照包装核对后重新评估。包装只提供五项营养时，可核对已有五项，其余保持空白；不会把碳水化合物当成糖，也不会把未标示项当成零。缺失项目无法判断，相关的当日余量显示未知。查看结果不写入摄入量，只有填写实际食用数量并点击「我已吃了，记入今天」才保存记录。旧版自动扫描记录保留供查看，不计入确认摄入。

新版区域 OCR 的附带资源合计约92 MB，包含服务版和双击版的两种工作线程封装，各入口只加载所需资源，使用同一 SDK 和模型。照片在浏览器本机处理。首次在线读取需下载资源，成功缓存后可再次使用；本地服务直接读取仓库附带的资源。旧 OCR 执行模块、调用分支和预缓存已移除，新引擎失败时明确报告错误，不会退回旧识别。本次已用提供的葡萄汁原图验证桌面浏览器中的源码、Pages 文件和 HTML 双击入口；微信、QQ 内浏览器及手机真机兼容留待后续验证。

修改 OCR 资源依赖后重新构建：

```powershell
npm ci
npm run build
```

仅修改 `src/` 时运行 `node tools/bundle-standalone.mjs` 和 `python -X utf8 tools/prepare-pages.py` 即可。构建依赖不需要在用户设备上安装。GitHub 更新后由 Pages 部署，实际生效版本以部署状态为准。

详细变更、操作步骤和检查命令见 [更新日志](更新日志.md)。
引擎来源、固定版本与许可证见 `assets/paddle/README.md`、`assets/paddle/manifest.json`。旧 `assets/ocr/` 是历史资源，不再加载或执行。

### 一条链接直达某个演示画面

答辩或录视频时不必每次点进去，直接把参数拼在地址里。
**下面这些链接在线上版也能直接用**（把域名换掉即可）：

| 链接 | 打开的画面 |
| --- | --- |
| `/` | 首页；首次打开会先进画像设置 |
| `?profile=allergy#/result?case=peanut-cookie` | 花生+牛奶过敏画像 → 红色警示 |
| `?profile=none#/result?case=plain-milk` | 基准画像 → 绿色结论 |
| `?reset=1#/result?case=sugar-drink` | 清空当日记录后 → 橙色警示 |
| `#/help` | 适老化对照表 |

两个参数的用途要说清楚，否则容易被结果绕晕：

| 参数 | 作用 | 为什么需要 |
| --- | --- | --- |
| `?profile=allergy` / `plain` / `none` | 预设画像（等同用户自己勾选，会**保存**下来） | 演示不用现场走五步设置 |
| `?reset=1` | 启动时清空当日记录 | 演示用例的结论依赖「今天吃了多少」，不清空的话同一个用例第二次打开等级会变 |

⚠️ `?profile=` 会**持久保存**。设成 `allergy`（花生+牛奶过敏）之后再打开纯牛奶，
它会正确地判成红色——这是引擎应有的行为，不是 bug。
想回到基准画像就加 `?profile=none`。

更多参数见 [tools/README.md](tools/README.md)。

## 二、五步闭环怎么走（演示动线）

| 步骤 | 在哪一屏 | 用户动作 |
| --- | --- | --- |
| 一 · 拍包装 | 首页 | 点一下大按钮，举手拍照 |
| 二 · 认标签 | 进度页 | 无需操作，看「正在看标签」 |
| 三 · 对画像 | 结果页 | 无需操作，系统读本地画像 |
| 四 · 判风险 | 结果页 | 看大字结论和颜色 |
| 五 · 念出来 | 结果页 | 听语音；核对完整营养信息后，可按实际食用数量确认记入今天 |

**首次进入**会走一遍画像设置：五个问题分成五屏，每屏一个大按钮，
全程没有一处需要打字。

### 三条离线演示用例（首页中部）

答辩现场网络不稳时用这三条，走的是内置数据，不走网络：

| 用例 | 演示的是 |
| --- | --- |
| 含花生的饼干 | 过敏原命中 → **红色**，一句话点名「别吃」 |
| 含糖饮料 | 一份糖 57 g → **橙色**，「今天甜的少来一点」 |
| 拍糊的照片 | 看不清就不下结论 → **灰色**，请用户补拍 |

想验证「同一件食品，不同画像结论不同」：把画像里的「花生过敏」勾上再看饼干，
红色；取消勾选再看，变黄色。**这就是规则层的确定性判断，不是模型猜的。**

### 演示模式开关（URL 参数）

| 参数 | 效果 |
| --- | --- |
| `?mock=high` | 仅显式调用 `recognizePhoto({ file, prefer: 'mock' })` 时控制模拟结果 |
| `?mock=low` | 仅显式指定模拟通道时控制低置信度；正常照片仍走真实 OCR |
| 默认 | 真实本机 OCR；演示商品仅通过演示入口使用 |

## 五、怎么把它变成你自己的

### 5.1 接真实识别接口（主通道）

只改 `src/recognize/config.js`：

```js
export const CONFIG = {
  vision: {
    endpoint: 'https://your-gateway.example.com/v1/chat/completions',
    authorization: 'Bearer sk-xxxx',
    model: 'qwen-vl-max-latest',
    ...
  }
};
```

兼容 OpenAI Chat Completions 的 `image_url` 格式，任何具备视觉能力的大模型都能接。
提示词已经写在同一个文件里（`VISION_PROMPT`），里面明确要求「看不清就填 null、
不要推测」，这份提示词可以直接贴进参赛材料的「AI 使用说明」。

> ⚠️ **前端放密钥 = 公开密钥。** 正式部署请把调用放到自己的服务端转发，
> `endpoint` 指向自己的转发地址，前端不放 AK/SK。云厂商的密钥泄露会被扫描到。

### 5.2 接华为云 OCR（兜底通道）

填 `CONFIG.huaweiOcr` 的 `endpoint / ak / sk / projectId`。
签名（SDK-HMAC-SHA256）已经用 Web Crypto 实现好了，不需要引入官方 SDK；
但华为云 OCR 的入参是**图片 URL 而不是文件流**，所以还需要一个 OBS 上传环节，
填 `uploadProxy` 指向你的后端即可（推荐，密钥不出后端）。

### 5.3 调阈值

`src/data/nutrition.js` 里的 `DAILY_LIMITS` 是唯一的阈值来源：

```js
sodium:       { limit: 1500, ... }   // 每日钠上限（mg）
sugar:        { limit: 25,   ... }   // 每日添加糖上限（g）
saturatedFat: { limit: 20,   ... }   // 每日饱和脂肪上限（g）
fat:          { limit: 60,   ... }   // 每日脂肪上限（g）
```

改完立刻跑一次自测，确认没有把结论改坏：

```bash
node tools/rule-selftest.mjs
```

### 5.4 加致敏物质别名

`src/data/allergens.js`：往对应类别的 `aliases` 里加词即可。
别名结尾带 `*` 表示「间接写法」，命中时置信度会略降并在依据里标注。

### 5.5 加一条演示用例

`src/data/sample-labels.js` 里追加一个对象，填 `expectLevel` 作为回归预期，
它就会自动进入自测用例集。

## 八、边界与合规

- 本工具只做日常饮食提醒，**不做疾病诊断**，不替代医生或营养师的意见。
- 所有风险判断基于公开国家标准与权威营养数据，判断依据可展开追溯。
- 系统明确区分「规则判定的确定性结论」与「模型推测的估算结果」，
  信息不足时主动要求补拍，不编造答案。
- 画像与记录**只存在本机浏览器**（localStorage），不上传、不共享、
  没有账号体系、没有埋点统计；照片仅在本机内存与相册中流转。
- 界面不含任何广告、插件、随机弹窗或诱导性按键。
- 识别结果中的演示用例数据为**构造数据**，不代表任何真实商品的标示内容。
